# Login-gated pages — these redirect any anonymous visitor (including
# crawlers) straight to login.html via client-side JS, so there is no real
# content here for a bot to index. NOT included: /impact.html or /impact/
# (see note below and in netlify.toml) — both must stay crawlable for
# social-preview bots to fetch shared post links.
Disallow: /feed.html
Disallow: /champions.html
Disallow: /profile.html
Disallow: /admin.html
Disallow: /login.html

# /impact.html is deliberately NOT blocked, even though the bare listing
# page also redirects anonymous visitors to login. Reason: impact-post.mjs
# sends real visitors (and therefore anyone copying a link from their
# address bar) to /impact.html?post=<slug> — a genuine, shareable per-post
# URL. A blanket "Disallow: /impact.html" blocks that too, since most
# crawlers match Disallow as a path prefix, not an exact string. Confirmed
# via Facebook's Sharing Debugger on 2026-07-26: that exact rule made
# facebookexternalhit refuse to fetch shared post links entirely (403,
# "robots.txt block"), breaking every Impact Post share on Facebook and
# likely LinkedIn. A $-anchored rule (blocking only the bare path) would
# fix this IF every crawler honored $ the way Google/Bing do, but that
# isn't confirmed for Facebook's crawler — and with sharing actively broken,
# this isn't the place to gamble on unconfirmed syntax. The downside of
# leaving it open is minor and one-sided: a JS-executing crawler hitting
# the bare /impact.html still gets redirected to login by the page's own
# client-side auth guard, same as it always did: robots.txt was never
# actually preventing that, only preventing bots from fetching the page in
# the first place, which is what broke sharing.
